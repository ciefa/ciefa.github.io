# Markdown replacement indentation: implementation specification

Date: 2026-09-23. Status: implemented and verified; see [testing.md](testing.md#markdown-indentation-coverage).
Baseline: `e84875c864aeb9728399d42419ad36ee09a09595`.

This specification is normative. Implement exactly the behavior, strings, files and tests below; it leaves no product decision to the implementer. The [Markdown workspace specification](markdown-workspace-implementation.md) remains in force except where section 8 amends it.

## 1. User outcome and scope

In a Markdown workspace, a reviewer restructures source with a suggestion, for example turning a flat list into nested groups:

```md
- **Einrichtung und Orientierung**
  - Erste Schritte am Computer
  - Erste Schritte auf dem Smartphone
```

The durable model, preview and exports already support multi-line replacements with leading whitespace. This release makes writing them practical in the replacement field:

1. **Tab / Shift+Tab** indent or outdent every line touched by the replacement field's selection, by two spaces.
2. **Escape, then Tab** leaves the field, so keyboard users are never trapped.
3. The replacement field, the selected-text quotes and the proposed replacements use a **monospace** font, so indentation is visible.
4. The replacement field is **taller** and grows with its content.

All four apply **only when the active document is Markdown** (`model.format === FORMAT_MD`). HTML reviews keep their current behavior byte-for-byte in the UI: Tab moves focus, the fonts and field height are unchanged, and the hint text is unchanged.

Out of scope: diff views for suggestions, insertion without a selection, indentation in the comment (`#note-input`) field, list-aware editing (auto-bullets, renumbering), configurable indent width, tab characters as indentation, and any change to saved formats, the durable model, the preview, exports or limits.

## 3. Pure function: `src/markdown/editing.js`

```js
export const INDENT = "  "; // two U+0020 spaces
export function indentLines(text, selectionStart, selectionEnd, outdent) → {
  changed, from, to, insert, text, selectionStart, selectionEnd
}
```

Preconditions (guaranteed by callers, not validated): `text` is a textarea value (only `"\n"` line breaks; browsers normalize CR/CRLF in the textarea API value), `0 <= selectionStart <= selectionEnd <= text.length`, `outdent` is a boolean. Offsets are UTF-16 string offsets.

**Affected lines.**

- `from` = start of the line containing `selectionStart`: `0` when `selectionStart === 0`, otherwise `text.lastIndexOf("\n", selectionStart - 1) + 1`. (The explicit `0` case is required: `lastIndexOf` with index `-1` would otherwise match a leading `"\n"`.)
- `last` = `selectionEnd - 1` if the selection is non-empty and `text[selectionEnd - 1] === "\n"`, else `selectionEnd`. A selection ending at the start of a line does not affect that line.
- `to` = `text.indexOf("\n", last)`, or `text.length` if none. `to` is exclusive and never includes a line break.
- `lines` = `text.slice(from, to).split("\n")`. A collapsed caret affects exactly its own line.

**Per-line change (`delta`).**

- Indent: prefix `INDENT` (`delta = +2`). Exception: when more than one line is affected, lines matching `/^[ \t]*$/` stay unchanged (`delta = 0`). A single affected line is always indented, even when empty.
- Outdent: remove the match of `/^(?: {1,2}|\t)/` if any (`delta = -1`, `-2`, or `0`). Only leading characters are removed.

`insert` is the rewritten `lines` joined with `"\n"`. `changed` is true when any `delta !== 0`. When unchanged, return the input `text` and selection, with `from`, `to` and `insert` still computed.

**Selection mapping.** Map each offset `p` against the original lines, accumulating `shift` (sum of deltas of earlier affected lines):

- `p` inside affected line `i` (`lineStart_i <= p <= lineStart_i + lines[i].length`), with `column = p - lineStart_i`: new offset `p + shift + Math.max(delta_i, -column)`. So positions move with inserted indentation, and positions inside removed indentation clamp to the line start.
- Exception: for a **non-empty** selection, `selectionStart` at column 0 stays at its line start (`p + shift`), so a selection of whole lines keeps covering them after indenting.
- `p` after the last affected line (only a `selectionEnd` excluded by the `last` rule): `p + total shift`.

**Required examples** (`→` shows `text`, `selectionStart`, `selectionEnd`, `changed`):

| # | Input text | Sel. | Mode | Result |
| --- | --- | --- | --- | --- |
| E1 | `"- a\n- b"` | 5,5 | indent | `"- a\n  - b"`, 7, 7, true |
| E2 | `"- a\n- b"` | 4,4 | indent | `"- a\n  - b"`, 6, 6, true |
| E3 | `"- a\n\n- b"` | 0,8 | indent | `"  - a\n\n  - b"`, 0, 12, true |
| E4 | `"- a\n- b\n- c"` | 0,4 | indent | `"  - a\n- b\n- c"`, 0, 6, true |
| E5 | `"- a\n- b\n- c"` | 2,9 | indent | `"  - a\n  - b\n  - c"`, 4, 15, true |
| E6 | `"  - a\n\t- b\n - c\n- d"` | 0,19 | outdent | `"- a\n- b\n- c\n- d"`, 0, 15, true |
| E7 | `"- a\n- b"` | 0,7 | outdent | unchanged, 0, 7, false |
| E8 | `"\n- a"` | 0,0 | indent | `"  \n- a"`, 2, 2, true |
| E9 | `"- a\n\n- b"` | 4,4 | indent | `"- a\n  \n- b"`, 6, 6, true |
| E10 | `"    - a"` | 1,1 | outdent | `"  - a"`, 0, 0, true |
| E11 | `"- a\n- b"` | 3,4 | indent | `"  - a\n- b"`, 5, 6, true |
| E12 | `"  "` | 0,2 | outdent | `""`, 0, 0, true |
| E13 | `"- 😀\n- b"` | 1,8 | indent | `"  - 😀\n  - b"`, 3, 12, true |

## 4. Replacement field behavior (`index.html`)

Add to the main application script, next to the existing composer functions (after `closeComposer`):

```js
let replacementTabRelease=false;
function fitReplacementInput(){
  const input=$('replacement-input');
  input.style.height='';
  if(model?.format!==FORMAT_MD || $('replacement-fields').hidden)return;
  input.style.height=Math.min(input.scrollHeight+2,Math.floor(window.innerHeight*0.6))+'px';
}
function indentReplacement(outdent){
  const input=$('replacement-input');
  const result=markdownWorkspace.indentLines(input.value,input.selectionStart,input.selectionEnd,outdent);
  if(!result.changed)return;
  // Replace only the affected lines through the editing command so browser undo restores them in one step.
  input.setSelectionRange(result.from,result.to);
  if(!document.execCommand('insertText',false,result.insert) || input.value!==result.text)input.value=result.text;
  input.setSelectionRange(result.selectionStart,result.selectionEnd);
  fitReplacementInput();
}
```

Register with the other listeners (after the `suggest-toggle` listener):

```js
$('replacement-input').addEventListener('keydown',e=>{
  if(model?.format!==FORMAT_MD || e.isComposing)return;
  if(e.key==='Escape'){replacementTabRelease=true;return;}
  if(e.key!=='Tab'){if(!['Shift','Control','Alt','Meta'].includes(e.key))replacementTabRelease=false;return;}
  if(e.ctrlKey || e.metaKey || e.altKey)return;
  if(replacementTabRelease){replacementTabRelease=false;return;}
  e.preventDefault();
  indentReplacement(e.shiftKey);
});
$('replacement-input').addEventListener('blur',()=>{replacementTabRelease=false;});
$('replacement-input').addEventListener('input',fitReplacementInput);
```

Rules this code encodes, which the tests assert:

- **Tab** always prevents the default focus move in Markdown mode, including when nothing changes (e.g. Shift+Tab on unindented lines). **Shift+Tab** outdents.
- **Escape** arms a one-shot release: the next Tab or Shift+Tab keydown performs the default focus move and disarms. Any other non-modifier key, or blur, disarms it. Escape keeps its existing document-level behavior (the listener does not stop propagation).
- Tab with Ctrl, Meta or Alt, and Tab during IME composition, are never intercepted.
- The first attempt applies text with `document.execCommand('insertText')` over the affected block only (one native undo step, fires `input`). If it returns false or produces a different value, assign `input.value` directly (undo history may be lost; the result is still correct).
- `hasDraftChanges`, `submitComment` and the newline normalization in `markdownWorkspace.replacement` are unchanged; indentation is ordinary field content.

**Auto-grow call sites.** Call `fitReplacementInput()`:

1. At the end of `showComposer`, after `$('replacement-fields').hidden` is set.
2. In the `suggest-toggle` change listener, after un-hiding the fields and before `focus()`: `$('replacement-fields').hidden = !$('suggest-toggle').checked; fitReplacementInput(); if (...) focus();`.
3. From `indentReplacement` (above) and the `input` listener.

Not on window resize. Auto-grow overrides a manual resize on the next input; `resize: vertical` stays enabled. In HTML mode `fitReplacementInput` only clears an inline height. The saved-copy template is cloned at startup, so inline heights never reach saved files.
